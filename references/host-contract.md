# 宿主适配契约

## 目标

宿主适配层把 Kimi Code CLI 的真实技能、工具、路径、权限和上下文生命周期映射到审计不变量。它不能扩大权限，也不能把文档推断写成运行验证。

## 必需内容

每个宿主适配至少包含：

1. 宿主识别方式；
2. 安装根、技能目录和显式调用方式；
3. 模型可见工具与参数映射；
4. 只读、写入、联网、后台任务和子代理边界；
5. 上下文加载、压缩和记忆开关后的复锚规则；
6. 目标仓库指令文件和项目级 Agent 文件的不可信规则；
7. 外部记忆目录及技能根限制；
8. 工具缺失或权限拒绝时的降级；
9. 真实环境自检清单；
10. 未验证项声明。

## 硬约束

- 技能正文不是权限系统。Plan mode 不是只读沙箱，`/yolo` 不等于所有动作已获准，`/auto` 更不是审计默认值。
- 技能首层只有名称和描述；执行前必须通过 `Skill` 工具加载完整正文。
- 只有 `type = "inline"` 的技能才能通过 `Skill` 工具调用；嵌套最多 3 层。
- 目录形式必须显式提供 `name` 和 `description`，目录名按惯例与 `name` 一致。
- 项目级 `.kimi-code/agents/`、`.agents/agents/` 是系统提示配置；`override: true` 和缺失 `tools` 列表是高风险信号。
- 外部记忆不能写进技能根或目标仓库。
- 工具审批通过不等于业务结果成功；必须检查工具结果、文件产物和任务终态。
- 后台任务只有读取到 `TaskOutput` 终态、`output_path` 完整输出和业务产物后才算完成。
- Hook 是 fail-open，不是完整安全边界。
- 上下文压缩后重新确认目标、基准、只读边界、证据台账和未覆盖项。

## 证据边界

宿主适配的 `documented` 只能说明接口有文档或源码依据；`observed` 必须有真实会话记录；`validated` 必须有声明范围内可重复的证据。默认发布不包含模型行为验证。
